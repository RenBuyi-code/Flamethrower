# 喷火机工程 TODO（AI执行版）

## 0. 目标与范围
- 目标：在现有 RTOS 基础上，构建可靠、安全、可移植、可扩展的软件架构与首版可运行功能。
- 代码原则：C 语言面向对象化（对象=结构体+接口函数+私有上下文），高内聚、低耦合。
- 范围基线：以 `doc/大喷火机客户给的需求.md` 与 `doc/DMX控制图.png` 为准。

## 1. 全局硬性约束（必须满足）
- C01: 安全优先级最高。任何异常状态必须在最短路径进入 `SAFE_OFF`（断点火/关锁油阀/按策略泄压）。
- C02: 业务层不得直接访问寄存器或芯片库类型；仅通过抽象接口 `hal_if/*`。
- C03: 执行器单写口约束：仅 `actuator_task` 可改动执行器输出状态，其他任务只能发命令。
- C04: ISR 极简：ISR 只采样/搬运数据/发通知，不做复杂逻辑与阻塞调用。
- C05: 任务通信仅使用 RTOS 原语（Queue/EventGroup/StreamBuffer/Timer），禁止全局变量无保护共享。
- C06: 关键参数（阈值、延时、DMX模式）必须有上下限校验和默认值回退。
- C07: 故障锁存：E1~E5 进入 FAULT 后需满足明确解除条件才可恢复。
- C08: 所有状态转移必须可追踪（日志/事件码）。
- C09: 不得破坏已有板级初始化与启动流程（`project/src/main.c` 仍是唯一启动入口）。
- C10: 可移植性要求：新增板卡仅替换 `bsp/<board>` 与 `cfg/board_profile_*`，不改 `domain`。
- C11: 动态内存约束：业务代码默认禁止 `pvPortMalloc/malloc`，优先静态分配。
- C12: 看门狗与任务心跳必须接入；任一关键任务失活需触发安全降级。
- C13: 引脚定义唯一来源必须是 `project/inc/at32f415_wk_config.h`；禁止在其他文件重复定义引脚宏。

## 3. 核心业务（domain）TODO
- T101 系统状态机（State 模式）
  - 状态：`BOOT -> SELFTEST -> READY -> FIRING/RELIEF -> FAULT/LOCKED`
  - 输出：`domain/machine_state.*`
  - 验收：状态迁移表完整，非法迁移被拒绝并记录。

- T102 安全守卫（Safety Guard）
  - 输入：压力/倾斜/电压/安全锁/DMX连通状态。
  - 输出：统一安全裁决 `ALLOW_FIRE | FORCE_STOP | FORCE_RELIEF | LOCKED`
  - 验收：任意故障输入均有确定动作。

- T103 故障管理器
  - 输出：`E1~E5` 触发条件、锁存、解除条件、上报码。
  - 验收：故障状态可重现可查询。

- T104 DMX 策略（Strategy 模式）
  - 模式：2CH/6CH 可切换。
  - 规则：严格按 `doc/两通道模式.csv`、`doc/六通道模式.csv`。
  - 验收：边界值（253/254、49/50/200/201、CH4=0/1/254/255）行为正确。

- T105 动作命令（Command 模式）
  - 输出：点火、停火、泄压、测试序列命令对象。
  - 验收：同一时刻命令冲突可仲裁，安全命令优先。

## 8. 禁止事项
- 禁止在 `domain` 写寄存器。
- 禁止多个任务直接操作执行器 GPIO。
- 禁止在 ISR 里执行状态机或业务决策。
- 禁止无校验地使用外部输入值（DMX/按键/ADC原值）。
- 禁止绕过故障锁存直接恢复喷火能力。

## 9. 交付定义（DoD）
- 功能：满足需求文档全部条目（含 2CH/6CH、TEST/USER、E1~E5）。
- 安全：任一异常场景都进入安全态，且可追踪。
- 质量：模块边界清晰，新增功能不改核心安全逻辑。
- 移植：更换板卡时，`domain` 与 `app` 无需重写。
