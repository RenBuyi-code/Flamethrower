- [x] LT-P2-02 实现第一版工业级 `middleware/easyDMX` 中间件并接入主链路。
  - 目标：替换 `freertos_app.c` 内联 DMX parser，形成可复用、面向对象、可靠解析的 DMX512 中间件。
  - 唯一数据源：`doc/DMX控制图.png`。`easyDMX` 和业务策略必须按图实现 6 通道模式与 2 通道模式，CSV/Markdown 只用于辅助核对，不作为最终裁决依据。
  - 图示规则必须落地：
    - 6CH：CH1/CH2/CH5 未使用；CH3 点火开关，0~253 不喷火，254~255 启动喷火；CH4 点火时间，0/255 永久喷火，1~254 为 10~2540ms；CH6 模式设置，0~49 泄压/急停，50~200 正常喷火，201~255 泄压/急停。
    - 2CH：CH1 点火开关，0~253 不喷火，254~255 启动喷火；CH2 模式设置，0~49 泄压/急停，50~200 正常喷火，201~255 泄压/急停。
  - 命名决策：目录使用 `middleware/easyDMX/`；公共头文件建议为 `easy_dmx.h`，C 符号统一前缀 `edmx_`，避免大小写路径和符号风格混乱。
  - 面向对象要求：提供 `edmx_port_t`、`edmx_rx_t`、`edmx_frame_t`、`edmx_stats_t` 等结构体；对象由调用方静态分配并注入缓冲区，不使用动态内存。
  - 环形缓冲要求：实现类似 Linux KFIFO 的 byte FIFO，支持 power-of-two 容量优化、head/tail 单调递增、mask 取模、可查询 used/free、溢出计数、丢弃策略。
  - 解析可靠性要求：可靠处理 BREAK、start code、512 通道边界、短帧、长帧、错误帧、丢帧、连续 BREAK、非 0 start code；输出稳定快照而非半帧数据。
  - 工业级要求：无阻塞、无 malloc、ISR/任务两种喂入方式兼容、统计帧率/错误/溢出/最近帧 tick、接口可单元测试、文档说明时序假设。
  - 业务联动：`easyDMX` 只负责可靠收帧和通道快照；`domain/dmx_strategy` 或后续 DMX 控制策略负责把图示规则转换成业务意图：`request_fire`、`request_relief`、`fire_duration_ms`。`control_task` 只消费业务意图，不直接解释通道号。
  - 集成策略：BSP 仍只负责 USART 字节和 BREAK 检测；`dmx_task` 将字节喂给 `easyDMX`；`control_task` 只读取已验证的最新通道快照/业务意图；安全裁决最终决定是否允许喷火或强制泄压/停火。
  - 验收：可喂入 break/start code/channel 字节序列并验证在线、帧完成、通道数组；按 `DMX控制图.png` 覆盖 2CH/6CH 全通道规则、253/254、49/50/200/201、CH4=0/1/254/255 和地址边界；溢出/短帧/非 0 start code 不产生危险点火意图。
  - 进度：已新增 `middleware/easyDMX/easy_dmx.[ch]`，实现面向对象接收器、KFIFO 风格 byte FIFO、BREAK/start code 解析、在线判断、统计字段，并已替换 `freertos_app.c` 内联 parser；待补 PC 单元测试和 HIL 压测。
